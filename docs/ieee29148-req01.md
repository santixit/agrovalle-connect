## Especificacion formal del sistema

**REQ-01.** El sistema debera permitir que una persona registre un perfil de agricultor cuando proporcione un nombre no vacio de hasta 120 caracteres, una cedula no vacia de hasta 30 caracteres que no este asociada a otro perfil y una ubicacion no vacia de hasta 80 caracteres dentro del Valle del Cauca. El sistema debera persistir el perfil, asignarle un identificador unico y devolver una confirmacion que incluya el identificador, el nombre y la ubicacion. La respuesta no debera incluir la cedula ni el hash de contrasena. Si se incluyen correo y contrasena para habilitar acceso, deberan proporcionarse ambos; el correo debera ser valido y unico, y la contrasena debera tener entre 10 y 72 caracteres. El sistema debera rechazar entradas invalidas o duplicadas sin crear parcialmente el perfil ni sus credenciales.

### Condiciones de cumplimiento

1. Entrada valida y cedula nueva: HTTP 201, identificador creado y perfil persistido.
2. Cedula duplicada: HTTP 409 y no se crea un segundo perfil.
3. Nombre, cedula o ubicacion vacios/fuera de longitud: HTTP 400 y no se persiste el perfil.
4. Solo se envia correo o solo contrasena: HTTP 400 y no se crea cuenta ni perfil parcial.
5. Correo duplicado: HTTP 409 y no se crea una nueva cuenta/perfil.
6. La respuesta omite cedula y credenciales.

Las reglas y limites anteriores se contrastaron con `RegistroAgricultorRequest`, `AgricultorService`, `AgricultorResponse` y `AgricultorController`. La ubicacion se valida como texto y el repositorio no contiene un catalogo que demuestre que el municipio pertenezca al Valle; si la docente interpreta “dentro del Valle” como validacion automatica, el equipo debe decidir si agregara un catalogo de municipios.
